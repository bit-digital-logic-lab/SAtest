# CSA共享行加法版

64个PE分别保存sum/carry，两数CSA每拍接收一组乘积；每个4×4共享四路两拍CPA，计算结束后相邻块交替出行、结果回写原PE。

共用A12W10、三拍乘法、INT32回绕、K向量II=1、8×8部分和输入/输出各8拍、8bank C存储。A/B独立端口；上传、计算和下载采用固定节拍，无反压。bias/oldsum直接装入原部分和寄存器。

## 本版的优势与代价

这是保留的“切分流水 CSA、4×4 集中最终累加”版本。

- **优势**：PE的每拍反馈只有逐位三压二，不经过完整32位CPA；每个4×4的16个PE共享4路最终CPA，整个8×8仅16路最终CPA。适合研究高频压缩累加与共享最终加法，且每拍只需8个A12、8个W10（176bit）。
- **代价**：每个PE要同时驻留32位sum/carry，状态量大；末尾交替出行及两拍CPA增加固定10拍/8×8。在150MHz实测中，面积、总周期均不如普通单拍版，不能因“用了CSA”就声称更省面积或更低功耗。
- **适用**：以CSA结构和高频路径为研究重点、能摊薄收尾开销的长K任务。本版已验证300MHz预布局setup；普通版未做同条件高频扫描，不能据此直接断言本版频率优于普通版。

### 切分流水与集中加法具体在哪里

```text
每PE： A12/B10 → kwt_mul[操作数寄存→部分积→合并，三级]
                           ↓ 每拍一个乘积
       kwt_csa32：[乘积、原sum、原carry] → 新sum/carry驻留
                           ↓ 计算结束后，按行选择
每4×4：16个PE → 4路kwt_row_adder → 回写当前行原PE的sum
                  第1拍：低16位相加，保存进位和两个高半字
                  第2拍：高16位带进位相加，与低半字拼接
阵列：相邻块隔拍交替送行 → 10拍收尾 → 每拍8个结果、8拍排完
```

这里“集中”指**每4×4共享四路**，不是整个阵列只有一个加法器；PE的CSA仍然驻留。最终结果写回原sum，carry清零，上传/排出复用原寄存器。

阅读顺序：[三级乘法](../../rtl/kwt_mul.sv) → [PE](rtl/kwt_pe_csa.sv) → [驻留CSA](rtl/kwt_csa32.sv) → [共享分段CPA](rtl/kwt_row_adder.sv) → [4×4块](rtl/kwt_quad4x4.sv) → [8×8调度](rtl/kwt_array_quad.sv)。

## 周期与验证

- 32×32×32任务：**1024拍**；99×64×256层（64任务）：**65536拍**，150MHz计算侧**7.425GOPS**。
- 完整回归28例、612728个最终输出逐点对齐，含随机尾块、零值、稀疏、补码极值、12层各2个真实样本及保留B/C重复累计。
- 测试台检查每个任务512次连续K向量发射，LOAD/STORE各128拍；逐拍检查下载行号。输入/输出8拍指阵列内部一整行8个INT32，顶层主机标量装载/回读和外部DMA时间不计入上述周期。

## 目录与复现

`rtl/`只放本版本的阵列、4×4块和PE算术；共用接口、乘法器、32×32控制在`hardware/rtl/`。CSA/普通版本虽有同名模块，脚本只读取所选版本目录，不同时混编。普通版编译32×32控制器时使用`TAIL_CYCLES=0`，CSA版为10，决定是否执行最终共享加法收尾。

在工程根目录运行：

```bash
python3 hardware/run.py --version csa --full --synth
python3 hardware/synth.py --version csa --scope all
```

## 提高频率后的结果

同一RTL重新以400MHz目标映射后，完整模块实际300MHz setup通过；1024拍任务3.413µs，65536拍整层218.453µs。实际边界为核心352MHz通过/353MHz失败、完整模块308MHz通过/309MHz失败，均为预布局结果。
