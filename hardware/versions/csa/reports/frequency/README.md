# CSA频率扫描与层时间

**不改变RTL或流水级数，本轮完整模块在300MHz通过预布局setup检查；300MHz时65536拍的一层计算时间为218.453µs。**

## 重新映射目标与实际时序

同一RTL分别以150、300、400MHz作为ABC映射与初始SDC目标，再对每份固定网表运行实际OpenSTA扫描。ABC映射为启发式优化；更严格目标可能选出更快的门/缓冲，因此“300MHz目标映射失败”不等于该RTL无法跑300MHz。最终使用400MHz目标映射出的网表，在300MHz重新施加完整SDC，核与模块均通过。

| 映射目标MHz | 核心面积mm² | 模块面积mm² | 实际300MHz核心slack ns | 实际300MHz模块slack ns | 核心最高验证通过MHz | 模块最高验证通过MHz |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 150 | 0.23356340 | 0.90033664 | -0.724388 | -0.749576 | 246 | 244 |
| 300 | 0.23357460 | 0.90034504 | -0.334796 | -0.375349 | 272 | 269 |
| 400 | 0.23406572 | 0.90105680 | 0.495205 | 0.096183 | 352 | 308 |

面积为标准单元面积，模块A/B/C存储采用触发器实现，尚未使用SRAM宏。400MHz是优化目标，**实际400MHz检查未通过**，不能把映射目标当作已达到的运行频率。

## 关键路径与下一步

- 核心的最差路径起于`finish_count[0]`，经高扇出控制/行选择分发到共享行加法流水；不是单独一个三压二算术门的延迟。
- 完整模块在400MHz目标映射后的最差路径从32×32地址/控制寄存器出发，经过C读回选择网络，终点为`c_data[28]`输出端口。当前统一SDC对这个组合读回口也预留0.5ns输出延时。
- 若继续提高完整模块频率，优先检查C读回接口寄存化及控制分发/扇出；核心控制也可在4×4局部生成以缩短高扇出路径。本轮没有修改这些RTL或接口。

此上限是**当前统一SDC、给定网表的预布局setup边界**，不代表CSA运算本身的绝对极限。没有布局布线、时钟树或寄生；本轮未做物理签核或板上频率测试。

## 约束与复现

ICsprout55 H7CL，SS/1.08V/125°C；clock uncertainty/transition各0.1ns，输入/输出延时0.5ns，输入transition0.1ns，输出负载0.01pF。所有有效端口有约束，未加入false path或multicycle。扫描每个频率均重新施加完整SDC，并检查check_setup报告。

```bash
python3 hardware/synth.py --version csa --scope all --frequency 400 --output .build/csa400
python3 hardware/frequency.py --mapping .build/csa400 --version csa --output .build/frequency400
```
