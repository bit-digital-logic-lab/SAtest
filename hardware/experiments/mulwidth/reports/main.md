# 4/8 乘法器 PE 与直接扩展矩阵对照

日期：2026-10-26  
源码已整理至 `hardware/experiments/mulwidth/`；历史测量路径 `.build/exp_mulwidth/` 保留在原始日志中，不属于正式 `hardware/versions/`。  
工具：Yosys 0.63 + Slang、ABC 6666.667ps、OpenSTA、55nm H7CL SS/1.08V/125°C、150MHz、预布局。

## 1. 结论

1. **同 MAC/拍下，多乘 PE 的核心面积确实更小，但只小约 10%～12%**：
   - 4 乘 8×8：0.6330 mm²，256 MAC/拍；16×16 单乘：0.7048 mm²，256 MAC/拍 → 多乘小 **10.2%**。
   - 8 乘 8×8：1.2429 mm²，512 MAC/拍；16×32 单乘：1.4102 mm²，512 MAC/拍 → 多乘小 **11.9%**。
2. **代价是 A/B 供数翻倍/2.75 倍，频率上限下降**：
   - 4 乘供数 704 bit/拍（2.75 bit/MAC），16×16 为 352 bit/拍（1.375 bit/MAC），正好 2 倍。
   - 8 乘供数 1,408 bit/拍，16×32 为 512 bit/拍，2.75 倍。
   - 150MHz 余量：4 乘 1.765 ns，8 乘 1.666 ns；16×16/16×32 约 2.63 ns。线性估计上限：4 乘约 204MHz，8 乘约 200MHz，16×16 约 248MHz。
3. **8 乘在 150MHz 仍然通过（1.666 ns），算术深度不是 150MHz 的硬墙**；真正的限制是 A/B 带宽和面积/输出。4→8 的 area/MAC 只再降 1.8%，供数却翻倍，**4 乘是性价比拐点，8 乘是“还能做但不划算”的上限**。
4. **直接 16×16 只比 4 乘 8×8 大 10.2%，但供数低 2 倍、每 tile 输出多 4 倍、面积/输出低 3.6 倍**。对本题这种 M=99、N=256、受搬运/调度限制的设计，16×16 直接扩展大概率比“每 PE 塞 4 个乘”更合适；4 乘只在“供数免费、只看 MAC 面积”时占优。
5. 8 乘 8×8 与 16×32 相比：核心小 11.9%，但供数 2.75 倍、每 tile 输出少 8 倍；不建议作为主线。

### 存储估算

按 K64 tile 计算：A=ROWS×64×12，B=64×COLS×10，C=ROWS×COLS×28；用当前块触发器风格
（DFF 6.16 µm²/bit，含读写 mux 约 12.07 µm²/bit）估算，仅作量级对照。

| 变体 | A/B/C bit | 存储估算 mm² | 核心+存储 mm² | 存储 bit/MAC |
|---|---:|---:|---:|---:|
| 8×8 m4 | 13,056 | 0.158 | 0.791 | 51.0 |
| 16×16 m1 | 29,696 | 0.358 | 1.063 | 116.0 |
| 8×8 m8 | 13,056 | 0.158 | 1.401 | 25.5 |
| 16×32 m1 | 47,104 | 0.568 | 1.978 | 92.0 |

等 MAC 下，多乘 PE 的核心+存储仍小约 26%～29%；但直接扩展每 tile 输出多 4/8 倍，
按“每输出”计，16×16 的 2,753 µm²/output 远低于 4 乘 8×8 的 9,891 µm²/output。
如果阵列是吞吐/面积按输出计，直接扩展更划算。

## 3. 周期侧

只算 K64 的 RUN 拍（不计 C 装载、等待、flush、下载）：

| 变体 | tile 数 | RUN 拍/tile | RUN 拍/层 |
|---|---:|---:|---:|
| 8×8 m4 | 416 | 16 | 6,656 |
| 16×16 m1 | 112 | 64 | 7,168 |
| 8×8 m8 | 416 | 8 | 3,328 |
| 16×32 m1 | 56 | 64 | 3,584 |

K 并行把 RUN 拍压下去，但 tile 数不变；2D 扩展用更大的 tile 把固定开销（LOAD/WAIT/FLUSH/STORE）
摊薄。两者 RUN 拍接近，实际总周期取决于 C 搬运算法和 bank 数。**4/8 乘并没有在周期上
明显赢过直接扩展**，因为 8×8 tile 的 C/控制开销被更多 tile 放大。

## 4. 验证

- DS-1：`kwt_pe_m4`、`kwt_pe_m8`，各 775 次逐拍比较、700 次有效累加、32 次零保持、5 次 load，错误 0；
  Yosys `check -assert` 0 problems。主代理已独立重跑 `run.sh`，输出 `ALL_OK`。
- DS-2：`kwt_pe_m1`、`kwt_flat16`，610 拍 PE + 20,736 点阵列比较，错误 0；
  主代理独立重跑，`OVERALL_PASS`。
- 主代理对 8×8 m1/m2/m4/m8、16×16、16×32 的全部顶层做了 Verilator lint，0 错误；
  Yosys 映射 `check -mapped` 0 problems。
- 8×8 扁平顶层只做结构/面积；功能算术由单 PE 和 16×16 阵列测试覆盖，未单独跑 8×8 全矩阵。

## 5. 结论与建议

- **如果只看“同 MAC 的乘法器核心面积”**：4 乘 8×8 比 16×16 小 10.2%，8 乘比 16×32 小 11.9%。
  这是“多乘 PE 省累加器/存储、但费 A/B 广播”的净结果；省得不多。
- **如果把供数/布线算进去**：4 乘的 A/B 是 16×16 的 2 倍，8 乘是 16×32 的 2.75 倍；
  频率上限也低 40～50MHz。**16×16 / 16×32 是更均衡的直接扩展**。
- **8 乘不是 150MHz 的硬极限**（仍有 1.67 ns 余量），但 4→8 的面积收益只有 1.8%，
  供数翻倍；**4 乘是拐点，8 乘是上限，16 乘不建议再试**。
- 下一步若继续：优先把 16×16 放进现有 32×32 块（A/B 1024、C 1024 刚好），
  验证 tile 数 112、C 搬运和 150MHz；4 乘 8×8 只在供数确实免费时作为备选。

## 6. 边界

- 预布局标准单元面积，不含布线、时钟树、A/B/C 宏；A/B/C 存储是触发器风格估算。
- 只比较计算核心；完整 block 的 A/B/C 地址映射、C 搬运 bank、功耗未展开。
- ACC28 为模 2²⁸、输出符号扩展；与 INT32 全宽回绕不是同一契约。
